# M1: Parser

## Context
PRD §6 M1: turn the saved SSSB widget responses (M0 fixtures) into `Listing` objects. Every field gets parsed, Swedish number formats included. A layout change raises an error and never yields silent zeros. Nothing touches the network; tests run only on `tests/fixtures/`. Saved to `docs/plans/M1.md` once approved.

What the fixtures showed:
- JSONP `cb({...});`. Listings are in `data["objektlistabilder@lagenheter"]` (24) and the total is in `html["objektsummering-TOTAL@lagenheter"]` (`"24"`).
- `hyra` uses a **non-breaking space** (`"3\xa0841"`). `yta` is an int or a float (`20.0`). `vaning` is `"1"`…`"20"` or `"Bottenvåning"`. `antalIntresse` is always `"N (Mst)"` in the fixtures.
- Flags are in `egenskaper[].beskrivning` ("10 mån hyra", "Elström ingår", "Max 4 år"). The detail widget's `egenskaper` is null.
- Detail: `html["objektintresse"]` holds "Kan bokas till 2026-11-30 klockan 16:00", and `html["objektintressestatus"]` holds "bokats av 5 personer, varav den med flest ködagar just nu har 132 ködagar".

## Code (new)
- `src/housing_watch/__init__.py` and `src/housing_watch/sssb.py` (one module, about 150 lines):
  - `ParseError(Exception)`, which carries the field, the raw value and the objektNr.
  - `Listing` (frozen dataclass): `id` (objektNr), `area`, `area_code`, `address`, `type`, `size_m2: float`, `rent: int`, `floor: int` (0 = Bottenvåning), `flags: tuple[str, ...]`, `move_in: date`, `published: date`, `top_days: int | None`, `applicants: int`, `detail_url: str`, `seen_at: datetime`. There is no deadline field: it comes from the detail request and is joined in M2/M3.
  - `Detail` (frozen): `deadline: datetime` (Europe/Stockholm, tz-aware), `applicants: int`, `top_days: int | None`.
  - `load_jsonp(text) -> dict`. `parse_list(payload, seen_at, *, check_total=True) -> list[Listing]`. `parse_detail(payload) -> Detail`.
  - Small helpers, each strict (regex fullmatch, otherwise `ParseError`): `parse_rent`, `parse_floor`, `parse_interest`, `parse_deadline`.
- `pyproject.toml`: add a `[build-system]` (uv_build) so `src/` imports work in pytest and in Actions later. No new runtime dependencies (stdlib `json`, `re`, `zoneinfo`; add `tzdata` only if CI lacks zone data).

## Strictness rules
- A missing required key, a wrong type, or a string that doesn't fully match its expected shape → `ParseError`. Never default to 0 or "".
- A list response without the listings key, or a TOTAL that isn't a number → `ParseError`. If `check_total` is on and the parsed count ≠ TOTAL → `ParseError` (TOTAL ignores filters, and we always fetch unfiltered).
- `typ`, `omrade` and flags are kept raw, with no whitelist. Deciding what is "a corridor room" is M3's rule engine.
- **Assumption (not in the fixtures):** a listing nobody has booked shows `antalIntresse` as null/"" or `"0 (0st)"`. Both become `top_days=None, applicants=0`. Any other shape raises. Corrected when a real one appears.

## Tests first (`tests/test_sssb.py`, see them fail, then implement)
1. The list fixture → 24 listings. The first one (`5102-3203-028`) matches every field exactly.
2. Across all 24: no rent ≤ 0, no size ≤ 0, every `top_days`/`applicants` present, ids unique.
3. Helpers: `"3\xa0841"` and `"3 841"` → 3841, `"13\xa0649"` → 13649; `"Bottenvåning"` → 0; `"132 (5st)"` → (132, 5); float `yta` kept.
4. Layout-change cases each raise `ParseError`: rent `"ca 3000"`/`""`/`None`, `antalIntresse "132"`, `vaning "Källare"`, a missing `objektNr`, a renamed listings key, TOTAL mismatch, input that isn't JSONP (an HTML page).
5. The empty fixture: `check_total=False` → `[]`. With the check on → `ParseError` (it proves the guard works).
6. Detail fixture: deadline = 2026-11-30 16:00 Europe/Stockholm, applicants 5, top_days 132. A sentence that no longer matches → `ParseError`.
