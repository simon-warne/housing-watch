# M0: Reconnaissance (no product code)

## Context
PRD §6 M0 is the gatekeeper step: find out how SSSB delivers listings and whether queue days are visible logged out, then save fixtures for M1, before any parser code. One GET during planning showed that `/lediga-bostader/` returns ~76 KB of HTML with **no listing data** (no "Rum i korridor", no "Ködagar: X"). The listings load through JavaScript, so the real source is another request.

## Steps (all GET, user-agent `housing-watch/0.1 (+github.com/simon-warne/housing-watch)`, ≥ 5 s between requests, ~20 requests in total)
1. **Find the data source.** Read the page's inline scripts and `wp-content/themes/fast2/client/behavior/compressed.js` for the URL that loads listings (likely an iframe, a JSON/JSONP endpoint, or a widget on another SSSB host). Check its robots.txt if it's a different host.
2. **Logged-out check.** Fetch that source logged out. If queue days and applicant counts are missing → **stop and ask Simon** (PRD: never log in).
3. **Fixtures** in `tests/fixtures/` (raw responses, dated filenames, plus a `README.md` that says where each came from and when):
   - listings page 1 (normal), page 2+, an empty result (page past the end, or a filter with no hits), one detail page with a "Kan bokas till …" deadline.
   - If the source is JSON, save the JSON; if it's HTML, the HTML.
4. **SSSB terms:** read the site's terms/cookie/privacy pages for anything that rules out automated reading. Note the result.
5. **GitHub Actions facts** (docs, cited): how late `schedule` runs start in practice, the 60-day inactivity pause for public repos and what resets it, minute limits for public repos.
6. **Where the database lives:** compare (a) a separate `data` branch with one commit per run that changed something, (b) Actions artifacts (90-day retention), (c) Actions cache (evicted after 7 days unused). Recommendation: **(a)**: durable and inspectable, and its commits also keep the repo "active" for the 60-day rule. Simon decides.
7. **ntfy from Actions:** once Simon has added the `NTFY_TOPIC` secret, a `workflow_dispatch`-only workflow `.github/workflows/ntfy-test.yml` sends one test push with the topic masked. This proves the secret → Actions → phone path. Skipped if he'd rather wait until M4.

## Output
- `docs/plans/M0.md` (this plan), `docs/reports/M0.md` (≤ 1 screen: findings, data source, logged-out answer, terms, Actions facts, DB recommendation), evidence (request log with status codes, response sizes and timestamps) in `docs/reports/evidence/`.
- `DECISIONS.md`: every yes from Simon (DB location, booked-marker approach, terms verdict).
- `STATUS.md` updated; tag `m0`. No `src/` code.
