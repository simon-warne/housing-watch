## New code (tests first for each)
1. **Fetching, in `sssb.py`:** `list_url()` and `detail_url(listing)`. `detail_url` takes the `refid` from `detaljUrl`, checks the host is `minasidor.sssb.se`, and builds the https widgets URL with the same three widgets as the M0 fixture. `http_get(url)` uses stdlib `urllib`: GET only, a 30 s timeout, user-agent `housing-watch/0.1 (+github.com/simon-warne/housing-watch)`. No new dependency for HTTP.
2. **`ntfy.py`:** `make_send(topic, post)` uses JSON publish to `https://ntfy.sh/` (UTF-8 titles are safe). It sends `{topic, title, message, priority: urgent 5 / high 4 / low 2, click: url, tags}`. Errors are re-raised without the URL or topic, and the reply is ignored.
3. **`crypto.py`:** Fernet from `cryptography` (new dependency: authenticated, a fresh nonce each time). It provides `encrypt(bytes, key)` and `decrypt(bytes, key)`. A wrong key raises, and the run stops loudly. It never starts a fresh state silently.
4. **`run.py`** (`python -m housing_watch.run --data DIR [--test-alert]`). It injects `get`, `send`, `sleep` and `now` so it can be tested offline:
   - It loads the config and env (`QUEUE_DAYS`, `QUEUE_DAYS_UNTIL`, `BOOKED_IDS`, `NTFY_TOPIC`, `STATE_KEY`). It decrypts `state.db.enc` to a temp file, or starts empty if the file doesn't exist yet.
   - **Politeness guard:** it skips fetching if the last fetch (in state `meta`) was under 25 min ago. That happens when a delayed `:07` run lands close to `:37`. The skipped run still re-encrypts and pushes, so it looks like any other.
   - It fetches the list, then `parse_list`. Detail pages go to listings that are `eligible` or in BOOKED_IDS and either have no known deadline (once) or close within 48 h (every run). The ones closing soonest come first, with at most 10 per run and `sleep(5)` before each request. `top_days`/`applicants` become the higher of the list and detail figures, then `record()`.
   - On success it calls `run_ok`, `listing_alerts`, `digest_alert` and then `dispatch`. On an exception or 0 listings it calls `run_failed(error)`, then `dispatch` (heartbeat), and exits with 1 after saving.
   - **Guard:** history's observation count must not shrink. If it does, the run aborts and pushes nothing.
   - It re-encrypts state and writes `DIR/ready`.
   - **Logs:** one fixed line, `ok: N listings` or `failed: <ErrorType>`. No alert counts, titles, days or exception text from sends.
   - `--test-alert` sends one fixed test alert through the real ntfy path. It isn't logged in state, and nothing is fetched.

## Workflow `.github/workflows/watch.yml`
- `schedule: cron "7,37 * * * *"`, plus `workflow_dispatch` (input `test_alert`). `concurrency: watch` (no overlap, no cancelling). `permissions: contents: write, actions: write`.
- Steps: checkout main, then `uv sync --locked`. Next, fetch the `data` branch into `data/` (empty on the first run) and run `run.py` with secrets passed only in that step's `env`. Then `scripts/push-data.sh` (`if: always()`, only when `data/ready` exists) makes an orphan commit of `history.sqlite` + `state.db.enc` and runs `git push --force origin data`.
- **Keep-alive:** in the first run after 03:00 UTC each day, `gh api -X PUT …/workflows/watch.yml/enable` runs (resets the 60-day timer from inside the workflow).
- **Backup:** on Sundays in that same slot, `upload-artifact` stores the two files for 90 days. History is public anyway, and state stays encrypted.
- `ntfy-test.yml` stays as it is.
- A test parses `watch.yml`. It checks that cron minutes aren't `0`, the `concurrency` is set, secrets appear only in step `env`, and there's no `set -x`/`echo` of secrets. The rules become tests, not reminders.
